# ADR-0002：打包 OFL 字体（霞鹜文楷屏幕版 + JetBrains Mono），而非系统栈或 CDN

- 状态：已接受（2026-11-19，三轮访谈收敛）
- 对应蓝图：PLAN.md §2 决策 6；非目标见 §3，字体装载见 §4、§5

## 背景

Kami 的排版气质高度依赖字体：霞鹜文楷（屏幕版）承担衬线层级，JetBrains Mono 承担代码。若依赖系统字体栈，字型随平台漂移——缺字、回退不一致，纸感无从保证。若走 CDN，则违反蓝图零网络约束（PLAN.md §3：无遥测、无字体 CDN、无更新检查），也在 Obsidian 审核与离线场景留下硬伤。可用的合规路径是把开源许可（OFL）的字体文件随插件打包分发。

## 决策

随插件打包两款 OFL 字体：霞鹜文楷屏幕版与 JetBrains Mono，并附带对应 LICENSE 文件（PLAN.md §2 决策 6，存放于 assets/fonts/）。运行时不发起任何字体网络请求。

取舍：放弃系统栈的零体积与 CDN 的省事，付出安装包体积显著增大（中文字体尤甚）与字体文件随版本维护的代价；换取全平台一致的字型气质、离线可用，以及审核上对零网络约束的干净交代。

## 后果

- 正面：渲染跨平台、跨设备一致，移动端同样成立；完全离线；审核无网络疑虑；OFL 允许随包再分发。
- 负面：插件体积明显增大；OFL 要求随包附带许可证并保留作者声明，字体升级时需同步维护；字体在插件目录内的装载方式若在移动端不可靠，需按蓝图退回内嵌方案（PLAN.md §5）。
