# ADR-0001：插件自带排版层，而非依赖 Kami Reader 主题

- 状态：已接受（2026-11-19，三轮访谈收敛）
- 对应蓝图：PLAN.md §2 决策 1；定位见 §1

## 背景

社区已有 Kami Reader 主题（KKenny0/obsidian-kami，纯 CSS），完成了全局静态换装与工作区外壳。但主题作为全局样式有天然边界：只能整体生效，做不到按笔记粒度控制、frontmatter 覆盖、JS 微动效，以及由数据驱动的行为。若本插件改为依赖该主题提供排版，则上述能力全部落空，且排版质量与更新节奏都受制于第三方仓库。前提是：这些按篇控制与动效能力，正是本插件的存在理由（PLAN.md §1）。

## 决策

插件自带完整排版层，不依赖任何主题（PLAN.md §2 决策 1）。与 Kami Reader 明确划界、互补而非竞争：主题管工作区外壳与全局换装，本插件管笔记内容的排版与动效。

取舍：放弃「薄封装、复用主题样式」的轻量路径，付出样式全量自持的维护成本，以及与主题并存时样式重叠的风险；换来按笔记粒度生效、frontmatter 覆盖、动效与合规的全部主动权。

## 后果

- 正面：按篇控制、frontmatter 覆盖、微动效均可实现；插件升级与主题更新互不牵制；无论用户装没装主题，排版表现一致。
- 负面：样式体量与维护成本由插件自担；用户同时启用 Kami Reader 时存在样式重叠，需在真实 vault 实测中确认并存表现；文档需持续说明互补定位，避免被误认为主题替代品或官方衍生。
