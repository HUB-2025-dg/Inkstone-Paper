# ADR-0003：动效仅阅读模式，Live Preview 只共享排版令牌

- 状态：已接受（2026-11-19，三轮访谈收敛）
- 对应蓝图：PLAN.md §2 决策 8；动效规格见 §8，作用域机制见 §5

## 背景

四项动效（滚动渐显、交互呼吸、聚焦阅读、打字机）都依赖对渲染结果的观察与干预。阅读模式渲染一次、结构稳定，适合承载它们；Live Preview 是编辑态，DOM 随输入频繁重排，且用户正在其中打字与定位光标——在编辑态跑动效，干扰输入、制造视觉噪声，还把性能开销摊进了高频路径。而 Live Preview 若连排版都不同源，同一笔记两种观感又不可接受。

## 决策

阅读模式承载完整体验：排版与全部四项动效（PLAN.md §2 决策 8）；Live Preview 只共享排版令牌（颜色、字号、间距等），不启用任何动效。

取舍：放弃「两模式动效所见即所得」的一致性，接受编辑态与阅读态的观感差异；换取编辑稳定、动效开销不进入编辑热路径，以及动效故障不伤及输入本身。

## 后果

- 正面：编辑不受动效干扰；性能开销只发生在阅读态；动效实现缺陷的最坏影响被限制在阅读视图；令牌同源保证排版在两模式间基本一致。
- 负面：同一笔记在两模式下动效表现不同，用户可能产生疑问，需在 README 说明边界；令牌需在两种模式间持续核对，防止后续演化中两套观感脱节。
